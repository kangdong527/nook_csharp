# ADR-004 그룹 생애: 첫 멤버와 마지막 멤버 탈퇴 시 삭제

- 상태: 채택됨
- 날짜: 2026-10-11 (2026-10-13 구현 결정 추가)
- 결정자: 강동진
- 작성: Claude (사용자 요청, 결정 내용은 D2-3 세션의 사용자 결정)

## 맥락

클래스 다이어그램에서 `Group`과 `GroupMember`의 다중성을 정하면서, 하한을 `0..4`로 둘지 `1..4`로 둘지 정해야 했다.
처음 안은 "멤버가 0명이 된 그룹은 남겨 두고 배치로 정리한다"였다. 그런데 이 안은 하한 `1..4`와 맞지 않고, 다음 문제가 있었다.

- 빈 그룹이 남아 있는 동안 **초대 코드가 계속 살아 있다.** 그 코드로 들어오는 합류와 정리 배치가 같은 그룹을 두고 경합한다
- 원본 nook의 "고아 그룹" 결함과 같은 상태가 정상 흐름에서 생긴다
- 배치(최종적 일관성)는 외부 I/O처럼 트랜잭션에 넣을 수 없는 작업(예: 스토리지 이미지 정리)에 쓰는 도구다. 탈퇴와 그룹 삭제는 둘 다 같은 애그리거트의 DB 작업이다

## 결정

1. **R-GR-08** 그룹을 만든 회원은 생성과 동시에 첫 멤버가 된다 → 멤버 없는 그룹은 만들어지지 않는다(생성 불변식, `Group.Create` 한 곳)
2. **R-GR-09** 마지막 멤버가 나가면 그룹도 **같은 트랜잭션에서** 삭제된다 → 멤버 0명인 그룹은 존재하지 않는다(생애 불변식)
3. 역할 분담
   - "마지막 멤버였는가"는 **루트(`Group.RemoveMember`)가 판정**해 결과로 알린다
   - 애그리거트 삭제는 저장소 작업이라 엔티티가 자기 자신을 지울 수 없다 → **Application이** 같은 트랜잭션에서 삭제한다
   - 불변식은 메서드 한 줄마다가 아니라 **트랜잭션 경계에서** 성립하면 된다
4. 동시성: 남은 두 멤버가 동시에 탈퇴하면 서로 다른 행을 지워 행 잠금 충돌이 없고, 둘 다 "1명 남음"으로 판단해 빈 그룹이 남는다(**Write Skew**). → 인원을 **세기 전에** 공통 행인 그룹 행을 잠근다. 그룹 생성도 R-GR-02 검사와 R-GR-04 사용자 행 잠금을 거친다
5. **구현(2026-10-13, D2 Group TDD)**
   - `RemoveMember`는 멱등이고 `enum MemberRemoval { NotMember, Removed, GroupEmptied }`를 돌려준다. 실패가 없으므로 `Result`가 아니다
   - `GroupEmptied`는 "방금 마지막 멤버가 나갔다"일 때만 나온다. 빈 그룹에서 다시 제거하면 `NotMember` → 삭제 신호가 두 번 나가지 않는다
   - `NotMember`를 enum 기본값(0)으로 둔다. 초기화되지 않은 값이 "아무 일도 없음"으로 읽혀 실수로 그룹을 지우지 않는다
   - 빈 그룹에 `AddMember`를 부르면 `InvalidOperationException`. 회원 입력이 아니라 `GroupEmptied`를 받고도 삭제하지 않은 호출 코드의 실수다
6. **방장(owner)은 두지 않는다(2026-10-13)**
   - 방장을 읽는 유스케이스(그룹 삭제·강퇴·이름 변경)가 없다. 그룹 삭제는 R-GR-09로만 일어난다
   - 넣으면 방장 탈퇴 시 위임·삭제 규칙과 회원 탈퇴(PF-02) 처리가 따라와 R-GR-09 흐름이 복잡해진다
   - 원본 nook의 `groups.owner_id ... on delete cascade`는 방장이 회원 탈퇴하면 **다른 멤버가 남은 그룹까지 삭제**한다. 읽는 곳 없는 값이 데이터 삭제 경로만 늘린 사례다
   - "누가 만들었나"는 첫 멤버의 `JoinedAt = CreatedAt`로 남는다

## 고려한 대안

- **빈 그룹 배치 정리**: 탈퇴 트랜잭션이 단순해진다. 그러나 정리 전까지 중간 상태(빈 그룹 + 살아 있는 초대 코드)가 존재하고, 합류·정리 경합을 따로 막아야 한다 → 기각
- **멤버 0명 허용(`0..4`)**: 불변식이 약해지고, 빈 그룹의 처리(조회 노출, 초대 코드 유효성)를 모든 유스케이스가 따로 다뤄야 한다 → 기각

## 결과

- 다이어그램 다중성은 `1..4`다. 분류표 "지키는 불변식"에 R-GR-08·09가 들어간다
- `RemoveMember`의 반환 타입이 "그룹을 지워야 한다"를 Application이 놓치지 않게 한다(결정 5). Application이 `GroupEmptied`를 받고 실제로 같은 트랜잭션에서 삭제하는지는 D5 통합 테스트가 확인한다
- D6에서 동시 탈퇴 Write Skew를 실제 PostgreSQL로 재현하고, 그룹 행 잠금으로 막히는지 확인한다(incident 후보)
- 합류는 사용자 행(R-GR-04)과 그룹 행(R-GR-03)을 둘 다 잠그므로, 데드락을 피할 잠금 순서를 D6에서 정한다
- 방장 기능이 필요해지면 `owner_id` 열을 추가하고 현재 멤버 중 `JoinedAt`이 가장 이른 회원으로 백필한다. FK `ON DELETE`는 CASCADE가 아니라 위임 규칙과 함께 정한다
