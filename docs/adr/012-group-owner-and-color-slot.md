# ADR-012 그룹 방장(만든 회원)과 멤버 색 슬롯

- 상태: 채택됨 — ADR-004 결정 6("방장 없음")을 번복한다
- 날짜: 2026-10-27
- 결정자: 강동진(PM 허가)
- 작성: Claude (사용자 요청, FE-2 세션)

## 맥락

FE 범위가 "원본 화면 전체"로 확정되면서(PM, 2026-10-27) 그룹에 두 가지가 필요해졌다.

1. **방장**: 그룹 이름 변경(GR-03)을 누가 하나. ADR-004는 "방장을 읽는 유스케이스가 없다"는 이유로 방장을 두지 않았다. 원본은 `owner_id`를 저장했지만 이름 변경 권한은 검사하지 않았고(멤버 누구나), `owner_id ... ON DELETE CASCADE` 때문에 방장이 탈퇴하면 **남은 멤버의 그룹까지 지워졌다.**
2. **색**: 그룹 지도에서 멤버마다 고유 색(PM: "모든 유저에게 색은 동일하게"). 색 값은 디자인 확정 전이다.

## 결정

| # | 질문 | 결정 |
|---|---|---|
| 1 | 방장 | 그룹을 만든 회원(R-GR-11). `groups.owner_id` NOT NULL, FK `users` **RESTRICT**(CASCADE 아님) + `ix_groups_owner_id` |
| 2 | 방장 권한 | 이름 변경만. 다른 멤버는 403 `Group.NotOwner` |
| 3 | 방장이 나가면 | 남은 멤버 중 가장 먼저 합류한 회원(동점은 user_id)에게 넘긴다. 나가기는 이미 그룹 행을 잠그므로(ADR-010) 같은 트랜잭션. 마지막 멤버면 그룹 삭제(R-GR-09)라 넘길 대상이 없다 |
| 4 | 방장이 탈퇴하면(PF-02) | 3과 같은 경로 — 탈퇴 절차가 멤버십을 지울 때 `Group.RemoveMember`를 거친다. RESTRICT가 이 절차를 건너뛰지 못하게 막는다(`fk_group_members_users`와 같은 원리) |
| 5 | 색 저장 | 색 값이 아니라 **슬롯 번호** `group_members.color_slot`(0~3 = 정원 4). 슬롯 → 색은 FE 한 곳. 디자인이 바뀌어도 마이그레이션 없음 |
| 6 | 색 배정 | 합류(·생성) 때 그룹 안에서 안 쓰인 슬롯 중 랜덤(R-GR-12). 랜덤 함수는 인자로 받아 테스트에서 고정한다(InviteCode와 같은 모양) |
| 7 | 색 중복 방지 | 합류가 그룹 행을 잠근 뒤 고르므로 동시 합류도 겹치지 않는다. `ux_group_members_group_color_slot`이 이중화, `ck_group_members_color_slot`(0~3) |

## 결과

- 원본 결함(방장 탈퇴 = 그룹 삭제)은 RESTRICT + 넘기기로 다시 생기지 않는다
- 기존 그룹 채우기: 마이그레이션 `AddGroupOwnerAndColorSlot`이 방장 = 가장 먼저 합류한 멤버, 슬롯 = 합류 순서로 채운 뒤 NOT NULL
- 원자성 테스트(`Create_WhenMemberInsertFails_LeavesNoGroup`)는 "없는 회원"으로 만들 수 없게 됐다 — `owner_id` FK가 groups INSERT를 먼저 막는다. 임시 CHECK로 group_members INSERT만 실패시키도록 바꿨다
- 확인: 도메인(방장·슬롯·넘기기·이름 변경), 통합(동시 합류 5건에서 슬롯 0~3 중복 없음, 방장 나가기 후 넘김 저장, CHECK 위반)
