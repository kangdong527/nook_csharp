# nook 서비스 완전 종료 런북

- 작성: 2026-11-07 Claude 정리(사용자 요청) · 2026-11-08 "서비스를 완전히 내리는 전체 프로세스"로 재구성(사용자 요청)
- 출처: AWS 콘솔 AI 어시스턴트 답변(사용자가 받은 내용) + Claude 보충. **공식 문서로 재확인하지 않은 항목은 ⚠️**
- 배경: 결정 7로 Paid plan(종량제) + 고급 기능(Organizations)을 켰다. 지출 한도(자동 차단)는 고급 기능 활성화로 **삭제**됐다 → 끄지 않으면 매달 청구된다
- 범위: 사용자 공지 → 데이터 파기 → 외부 연결 해제 → AWS 자원 삭제 → 도메인 → 비용 0 확인 → 계정 닫기 → 저장소·로컬 정리
- ⚠️ 이 문서의 자원 목록은 **계획 기준**이다. 실제로 만든 것은 맨 아래 "실제로 만든 과금 대상" 표가 기준 — 자원을 만들 때마다 그 표에 추가한다

## 0. 원칙 (순서의 이유)

| 원칙 | 이유 |
|---|---|
| **의존하는 것부터 끊고, 이름(도메인)은 마지막에 놓는다** | 풀린 도메인·S3 버킷 이름은 **남이 다시 가질 수 있다**. 새 주인이 메일 수신·사이트 게시·옛 링크 가로채기를 할 수 있음 |
| **배포 경로를 먼저 막는다** | CD가 살아 있으면 지운 자원을 `main` 머지 한 번이 다시 만들거나 오류 루프를 돈다 |
| **데이터는 사본까지 지운다** | DB만 지워도 백업(S3)·스냅샷(EBS)·로그에 개인정보가 남는다 |
| **CloudTrail은 거의 마지막에 지운다** | 삭제 작업 자체를 감사 기록으로 남긴다 |
| **계정을 닫는 건 비용 0을 확인한 뒤** | 닫은 뒤에도 남은 자원이 있으면 90일 post-closure 동안 과금될 수 있다 |

## 4. 외부 연결 해제

| 대상 | 할 일 | 안 하면 |
|---|---|---|
| **SES** | 도메인 ID(DKIM 포함) 삭제 | DNS를 넘긴 뒤 새 도메인 주인이 nook 이름으로 발송한 것처럼 보일 수 있음 |
| **카카오 개발자 콘솔** | 사이트 도메인·Redirect URI에서 nook 도메인 제거, 앱 삭제(또는 비활성) | 남이 산 도메인이 허용 출처로 남음 |
| **GitHub OIDC** | AWS IAM의 OIDC 공급자·배포 역할 삭제(6-1에서 함께) | 신뢰가 남아 있으면 리포 쪽에서 역할을 다시 받을 수 있음 |

## 6-1. AWS 자원 삭제 (nook-prod)

순서는 **의존 관계의 역순**(쓰는 쪽 → 쓰이는 쪽). 작업 전 우측 위 **계정(ID로 확인)과 리전** 확인.

| # | 자원 (만든 단계) | 방법·주의 |
|---|---|---|
| 1 | EC2 인스턴스 (5) | 종료(terminate). **루트 볼륨 "종료 시 삭제"가 꺼져 있으면 볼륨이 남는다** |
| 2 | EBS 볼륨 (5) | 남은 볼륨 삭제(데이터 볼륨을 따로 붙였다면 특히) |
| 3 | 탄력적 IP (5) | 인스턴스에서 떼기만 하면 계속 과금 → **해제(release)** |
| 4 | DLM 정책 → EBS 스냅샷 (9) | 정책을 먼저 지워야 새 스냅샷이 안 생김 |
| 5 | ECR 리포지토리·이미지 (8) | 리포지토리 삭제(이미지 포함, `--force`) |
| 6 | S3 버킷 (5·9) | 3절대로 비운 뒤 삭제. 버킷 이름도 남이 재사용 가능 → 코드·문서가 옛 이름을 가리키지 않게 |
| 7 | SSM Parameter Store (6) | SecureString 파라미터 삭제 |
| 8 | CloudWatch Logs 로그 그룹 | 보존 기간 무기한이면 계속 쌓임 |
| 9 | SES (7) | 4절에서 처리. 이메일 ID도 삭제 |
| 10 | IAM | 인스턴스 역할·인스턴스 프로파일, OIDC 배포 역할·OIDC 공급자, `nook-readonly` 역할(마지막 — 검증에 쓴 뒤) |
| 11 | 보안 그룹 (5) | 기본(default) 외 SG 삭제(무료지만 정리) |
| 12 | Route 53 레코드 | 6-2에서 |

## 7. 비용 0 확인

| 확인 | 방법 |
|---|---|
| **모든 리전**의 남은 자원 | Resource Explorer 또는 Tag Editor(리전 "All"). 다른 리전에 실수로 만든 자원이 가장 흔한 누락. SCP로 서울·필수 리전 외는 막혀 있지만 버지니아·오리건·시드니도 확인 |
| CLI로 교차 확인 | `nook-readonly`로 EC2·EBS·EIP·S3·ECR·스냅샷 목록이 비었는지(aws-account-setup 9절 명령 재사용) |
| Cost Explorer | 서비스별 **일 단위** 비용이 0으로 떨어졌는지(하루 이틀 지연) |
| 지원 플랜 | Business Support+ 등 유료 지원 없음(2026-11-07 확인됨) |

## 8. AWS 계정 닫기 (완전 탈퇴)

```
① CloudTrail 트레일 삭제 → 로그 버킷 비우고 삭제 → ② 프로젝트(멤버 계정) 닫기 → ③ 관리 계정 닫기 → ④ Builder ID 삭제(선택)
```

| 단계 | 방법 | 조건·메모 |
|---|---|---|
| ① CloudTrail | Management → 트레일 `nook-org-trail` 삭제 → 로그 버킷 비우고 삭제 | **명시적으로 지우지 않으면 닫은 뒤에도 과금될 수 있음**(어시스턴트). 감사 기록을 위해 6-1 뒤에 |
| ② 프로젝트 닫기 | AWS Settings → 프로젝트 선택 → **Close project** — nook-prod, nook Identity Delegated Admin | 90일 post-closure(데이터 보존). 남은 자원이 있으면 이 기간 과금 가능 |
| ③ 관리 계정 닫기 | AWS Settings → Project → Actions → **Close management account** | **모든 프로젝트를 닫은 뒤에만** 가능. 90일 post-closure. Budgets 2개도 함께 사라짐 |
| ④ Builder ID 삭제(선택) | `profile.aws.amazon.com` → Privacy & data → **Delete AWS Builder ID** | 관리 계정을 닫은 뒤. 무료라 안 지워도 비용 없음 |

```
계정 닫기 (예: X월 X일)
   ↓  닫기 전까지 쓴 요금 → 다음 달 초 1회 청구
90일 post-closure 기간 (데이터 보존 — 남은 자원이 있으면 계속 과금될 수 있음, 이 기간엔 Support로 재개 가능)
   ↓
90일 후 영구 삭제 → 이후 청구 없음
```

| 주의 | 내용 |
|---|---|
| 마지막 청구 | 닫기 전 사용분은 다음 달 초 1회 청구 → **Billing → 청구서**에서 그 다음 달이 0인지 확인 |
| 같은 이메일 재사용 | 탈퇴 후 같은 이메일로 새 계정 불가 → 루트 이메일 `+aws` 별칭이 유리(다른 별칭으로 새로 만들 수 있음) |
| 소셜 로그인 | Builder ID를 지워도 Google/Apple 계정 자체는 그대로 |
| 지출 한도 | 어시스턴트가 권한 "Spend Limit 설정"은 **고급 기능 활성화로 삭제됨** → 해당 없음. 비용 감지는 Budgets(③ 전까지) |
